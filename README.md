# BoxCRM — CRM для малого бизнеса на Django

Учёт товаров, продаж, списаний и клиентов для небольшого магазина. Два приложения:
`core` (пользователи, роли, клиенты) и `shop` (товары, журнал операций, аналитика, Excel).
SQLite, Django Auth, Django Templates + Bootstrap 5, логотип BoxCRM.

## Возможности

- **Товары:** таблица с поиском, остатки, цена и закупка, статусы «В наличии / Мало / Нет».
- **Продажа в один шаг:** модальное окно с количеством (по умолчанию 1) и способом оплаты
  «Наличные / Безнал-Карта». Остаток списывается, операция пишется в журнал без перезагрузки страницы.
- **Проверки:** нельзя продать или списать больше остатка, а закупочная цена не может быть
  выше цены продажи.
- **Редактирование и удаление** — модальные окна на главной, без переходов на отдельные страницы
  и без перезагрузки (fetch + JSON).
- **Журнал:** дата, товар, действие, количество, причина списания, способ оплаты, автор.
  Фильтры: Сегодня / Вчера / За неделю / За месяц.
- **Аналитика (только владелец):** финансы, товары, сотрудники и контроль списаний.
  Периоды: Сегодня / Неделя / Месяц.
- **Клиенты:** список, добавление, удаление.
- **Excel:** экспорт товаров, пустой шаблон и импорт с обновлением цены и закупки.
- **Роли:** владелец (суперпользователь) и продавец (обычный пользователь).
- **Дизайн:** синий бренд, белые карточки, скругления, адаптив под мобильные.
- **Без интернета:** Bootstrap и логотип лежат в `static/`, CDN не используется.

## Быстрый старт (Windows без активации venv)

```powershell
cd mycrm_real
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt

.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py createsuperuser
.venv\Scripts\python.exe manage.py runserver
```

Откройте **http://127.0.0.1:8000/** и войдите под созданным суперпользователем.

### macOS / Linux

```bash
cd mycrm_real
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Демо-данные (необязательно)

```powershell
.venv\Scripts\python.exe manage.py seed_demo
```

Создаст 5 товаров с ценами и закупкой (Ручка, Тетрадь, Мыло, Порошок, Блокнот),
двух клиентов, стартовый приход и две демо-продажи — чтобы вкладка «Аналитика»
сразу показывала цифры.

## Быстрый сброс пароля администратора

В корне проекта есть `reset_password.bat`. Двойной щелчок:

- создаёт суперпользователя `admin`, если его нет;
- сбрасывает пароль на `admin123`;
- при необходимости сам применяет миграции.

Или вручную:

```powershell
.venv\Scripts\python.exe reset_admin_password.py
```

После этого вход: логин `admin`, пароль `admin123`.

> Пароль `admin123` — только для локального запуска. Смените его в админке перед публикацией.

## Роли

| Роль | Как получить | Что видит |
|---|---|---|
| **Владелец** | суперпользователь (`createsuperuser` или `reset_password.bat`) | всё: товары, журнал, аналитика, клиенты, добавление/редактирование/удаление, импорт Excel |
| **Продавец** | обычный пользователь без прав staff/superuser | товары и клиенты, «Продать» (с количеством и оплатой) и «Привезти» |

### Создать продавца

1. Войдите владельцем и откройте **/admin/**.
2. **Пользователи → Добавить пользователя**: логин и пароль.
3. **Не** отмечайте «Статус персонала» и «Суперпользователь».
4. Сохраните — этот пользователь работает как продавец.

### Переключатель ролей в шапке

У суперпользователя в шапке есть переключатель **Владелец / Продавец** — это режим предпросмотра:
можно проверить, как интерфейс выглядит для продавца. Режим хранится в сессии и не меняет права
в базе. У обычного продавца переключателя нет — только имя и кнопка «Выйти».

## Продажа товара

1. Кнопка **«Продать»** в строке товара открывает модальное окно.
2. Укажите количество (по умолчанию `1`, можно ввести `25`) — подставляется остаток по товару
   и проверяется, что продать больше остатка нельзя.
3. Выберите способ оплаты: **Наличные** (по умолчанию) или **Безнал/Карта**.
4. **«Подтвердить»** — остаток уменьшается, в журнал пишется операция с количеством и способом
   оплаты. Страница не перезагружается: обновляются строка товара и итоги сверху.

Если товара нет на складе, кнопка «Продать» открывает окно с предупреждением и блокирует
подтверждение — сначала оформите приход. Если указать количество больше остатка, появится
ошибка «Недостаточно товара на складе» и операция не пройдёт.

## Закупочная цена и прибыль

- У товара два поля: **Цена** (продажи) и **Закупка**.
- Закупка заполняется при добавлении товара и в модалке редактирования.
- Если закупка выше цены продажи, форма вернёт ошибку «Закупочная цена не может быть выше цены продажи».
- В журнал записывается цена и закупка **на момент операции** — изменение цены задним числом
  не искажает историю и аналитику.
- Владелец видит колонку «Закупка» в таблице товаров; продавцу она не показывается.

## Аналитика

Вкладка **«Аналитика»** доступна только владельцу (`/analytics/`). Фильтры:
**Сегодня / Неделя / Месяц** (неделя — последние 7 дней, месяц — последние 30 дней).

### Финансы

- **Выручка** — сумма продаж за период по цене на момент продажи.
- **Прибыль** — выручка минус закупочная стоимость проданного, плюс маржа и сумма закупки.
- **Наличные** и **Безнал/Карта** — суммы и количество оплат по каждому способу.
- Если у проданных товаров не заполнена закупка, показывается предупреждение:
  прибыль может быть завышена.

### Товары

- **Топ-5 по продажам** — по количеству, с выручкой.
- **Топ-5 «мёртвых»** — не продавались за период (сначала те, где заморожено больше остатка).
- **Скоро закончатся** — остаток 5 шт и меньше.

### Сотрудники

Таблица **«Имя продавца | Сумма продаж | Количество чеков»** за период и строка «Итого».
Один чек = одна операция продажи, поэтому продажа 25 шт за раз считается одним чеком.

### Контроль

Отчёт **«Подозрительные списания»**: сумма списаний с причиной «Недостача» по каждому
продавцу. Если сумма больше **1 000 ₽** за период, строка подсвечивается красным со статусом
«Проверить». Недостача оценивается по закупочной цене, а если она не задана — по цене продажи.
При списании владелец может указать **ответственного сотрудника** — тогда недостача попадёт
в его строку отчёта (если не указан, она числится за владельцем).

## Excel

### Экспорт

Кнопка **«Экспорт в Excel»** на странице товаров скачивает `boxcrm-products-ГГГГММДД.xlsx`
с колонками **Название, Цена, Закупка, Количество**.

### Шаблон

На странице импорта есть **«Скачать шаблон»** — пустой файл `boxcrm-template.xlsx`
с правильными колонками и оформлением.

### Импорт

Кнопка **«Импорт из Excel»** (только владелец) принимает `.xlsx`:

- колонки **Название**, **Цена**, **Закупка**, **Количество**
  (или `name`, `price`, `purchase`, `quantity`, а также «Цена, ₽», «Кол-во»);
- лист с заголовками находится автоматически, читаются все строки всех подходящих листов;
- если товар с таким названием уже есть — обновляются **цена и закупка**;
- **количество существующих товаров не меняется** — защита от перезаписи остатков;
- если товара нет — создаётся новый с количеством и закупкой из файла;
- пустая или некорректная закупка у существующего товара не затирает текущее значение;
- числа понимают запятую, пробелы и знак `₽` (`1 234,56` → 1234.56);
- полностью пустые строки пропускаются и не считаются ошибкой;
- строки с пустым названием, ценой не числом или закупкой выше цены пропускаются;
- после импорта показывается отчёт: **всего строк / создано / обновлено / пропущено**
  и таблица пропущенных строк с причиной.

## Настройки

Настройки читаются из переменных окружения (значения по умолчанию — для локального запуска):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DJANGO_SECRET_KEY` | dev-ключ | секретный ключ Django |
| `DJANGO_DEBUG` | `1` | `0` — выключить debug |
| `DJANGO_ALLOWED_HOSTS` | `127.0.0.1,localhost` | список хостов через запятую |
| `BOXCRM_DB` | `db.sqlite3` | путь к файлу базы |
| `DJANGO_TIME_ZONE` | `Europe/Moscow` | часовой пояс для «Сегодня» в аналитике и журнале |

Для продакшена обязательно: свой `SECRET_KEY`, `DJANGO_DEBUG=0`, правильные `ALLOWED_HOSTS`,
`collectstatic` и нормальный веб-сервер.

## Частые проблемы

| Симптом | Решение |
|---|---|
| `ModuleNotFoundError: No module named 'django'` | Установите зависимости и запускайте через Python из venv |
| `no such table: shop_product` | Выполните `python manage.py migrate` |
| Забыли пароль администратора | Запустите `reset_password.bat` |
| После обновления не работают модалки/кнопки | Обновите страницу через Ctrl+F5: браузер мог закешировать старый `app.js`. В проекте статика версионируется (`app.js?v=...`) |
| После обновления на сервере не видны изменения | Выполните `collectstatic` и перезапустите приложение |
| Продавец видит лишнее | Убедитесь, что у пользователя нет прав staff/superuser |
| Excel не импортируется | Нужен файл `.xlsx` с колонками Название, Цена, Закупка, Количество |
| «Сегодня» в аналитике не совпадает с местным временем | Задайте `DJANGO_TIME_ZONE` (например, `Asia/Yekaterinburg`) и перезапустите сервер |
| Не отображается логотип | Проверьте папку `static/icon/` и выполните `collectstatic` для продакшена |
